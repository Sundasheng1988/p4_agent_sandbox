# Roadmap

## 总览

P4 Agent Sandbox 的目标是构建一个具备：
- 知识理解能力（Knowledge Runtime）
- 工具调用能力（Tool Use）
- 规划能力（Planning）
- 自我校验能力（Reflection）

的最小可演进 Agent 系统。

---

# Milestones

## M1 Runtime Foundation ✅
- Orchestrator 基本流程
- SafeToolExecutor
- Trace / Audit 机制
- 基础工具调用链路

---

## M2 Knowledge Runtime ✅
- 文件上传与管理
- 文本解析（parse）
- 索引构建（index）
- 全文搜索（keyword search）

## M4 Agent Intelligence（进行中）

目标：让系统具备“决策能力”，而不是仅靠规则路由。

---

### M4.1 LLM Planner v1 ✅（已完成）

实现：

- 引入 LLM 作为 Planner（Qwen / Ollama）
- 根据自然语言生成 Tool Plan（JSON）
- 单步规划（0 / 1 step）
- 严格 JSON 校验 + schema 验证
- 工具 allowlist 过滤
- Planner 审计日志：
  - `planner_llm`
  - `planner_fallback`

Fallback 机制：

- LLM 失败 → 自动回退 rule-based planner

能力边界：

- 能稳定识别以下意图：
  - 搜索类（knowledge_search / semantic）
  - 构建类（build_*）
  - 问答类（rag_answer）
  - 重置类（reset）

当前状态：

- 已通过多条真实输入测试
- 具备基础泛化能力（非模板句）
- Planner → Executor → Tool 全链路稳定

---

### M4.2 Multi-step Tool Use（下一步）

目标：

让 Agent 能执行 **多步任务链**，而不是单步工具调用。

核心能力：

- 支持 N-step plan（>1 step）
- step 之间数据传递
- 上一步输出 → 下一步输入
- 基础 execution loop

示例：

用户输入：
“帮我总结所有上传文档的内容”

期望 plan：

1. files_list
2. file_read / parse
3. summary

---

### M4.3 Reflection / Verification

目标：

让 Agent 能判断“结果是否可信”。

能力：

- 检查 tool result 是否为空 / 异常
- 判断回答是否与 query 对齐
- 自动 retry / re-plan
- 基础 self-critique

---

### M4.4 Hybrid Planner（LLM + Rule）

目标：

构建更稳定的生产级规划系统。

能力：

- LLM Planner + Rule Planner 混合决策
- 基于规则的 guardrail
- 高风险操作（reset / destructive）强制 rule 校验
- planner scoring / ranking（可选）

---

# 当前状态总结

当前系统已达到：

> **LLM 驱动的单步 Agent（可用级）**

能力组合：

- Knowledge Runtime（结构化 + 语义）
- RAG Answer
- LLM Planner（单步）
- Tool Execution + Policy + Audit

# 下一阶段重点

优先级建议：

1. M4.2 Multi-step Tool Use（核心能力跃迁）
2. Planner 输出结构标准化（为多步做准备）
3. 引入 step-level context（执行上下文）
4. 简单 memory / state（可选）

# 风险与注意点

- Planner hallucination（选错工具）
- JSON 输出不稳定（需严格解析）
- 多步执行中的中间状态丢失
- 工具之间 schema 不统一
